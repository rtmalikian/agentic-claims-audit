# EVALS.md — evals were written FIRST

Order of construction in this repo, deliberately:

1. **Gold dataset** (`evals/dataset.json`, generated by `evals/generate_dataset.py`): 120 synthetic claims with gold categories — clean (24), duplicate (24), upcoding (24), missing documentation (16), medical-necessity-questionable (16), bundling (16). The agent only ever sees the *agent view* (gold fields stripped; leakage-checked in tests).
2. **Graders** (`aca/evals.py`): exact-match on category; citation check (a finding counts only if a cited retrieved document actually supports it); LLM-as-judge behind an interface — a deterministic local judge for offline CI and an OpenAI-compatible judge client for a real model endpoint.
3. **Bias & leakage checks**: a position-bias probe (the same finding presented in both orders must score the same) and a gold-label leakage scan over the agent-visible payload.
4. **Regression thresholds**: precision ≥ 0.80, recall ≥ 0.80, citation rate ≥ 0.95 — `regression_gate()` in `aca/evals.py`; CI fails below threshold.
5. **Only then the agent** (`aca/agent.py`), graded against all of the above.

## Production feedback loop

Offline evals go stale. `POST /feedback` records a reviewer's correction on a finding; `aca/feedback.py` converts each correction into a new `EvalCase` with `source="reviewer_correction"`, i.e. every corrected production mistake becomes a regression test case. `aca/report.py` compares offline (gold set) vs online (reviewer-corrected) precision/recall/citation rate and flags drift ≥ 0.10.
